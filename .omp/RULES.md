# Vox 硬规矩（每次都生效）

1. **未经用户明确要求，不 `git commit`、不 `git push`、不改远端**。
   - **例外（用户已授权，2026-09-22）**：本项目当前允许**每轮收口时分组提交并推送**（core / mcp / headless / net / app / docs+tools 分组）；
     授权撤销前，收口提交属允许动作，但**推送前仍要确认门全绿**（`cargo fmt --all --check` + `cargo test --workspace` + `cargo clippy --workspace --all-targets`）。
2. 回复用户用**中文**；文档用中文；代码标识符/注释可英文。
3. **代码与文档冲突时以代码为准**，然后回头改文档（不是改代码去迁就文档）。
4. **不许留 TODO / 占位 / 假实现 / 空函数钩子**；做不完就明说缺什么前提，不要塞半成品。
5. **改公共接口必须迁移全部调用方**，不留 shim / 别名 / 兼容分支。
6. **热路径（音频回调、DSP 每帧、渲染每帧）不许新增分配或拷贝**；优化要有测量，不靠直觉。
7. **测试只写会因真实 bug 失败的**；不许为了让测试过而改测试契约（契约本身错了要先说明）。
8. **一个文件一个 owner**；同一轮里多个代理不许同时改同一文件，冲突找 Main 排。
9. 破坏性/不可逆操作（删文件、改仓库外配置、装系统包）先问用户。
10. **报告里的“零命中 / 全绿 / 全部一致 / 已核过”必须是真跑出来的**：贴命令与原始输出；跑不了就写“未跑”。
    已发生两次同类事故（写了没跑过的 grep、把 pattern 里没有的模式说成零命中）——这类句子一律按假证据处理。
11. **引用要耐久**：施工单/报告优先写符号名（`Type::method` / `file.rs::fn`），行号只作参考并注明“哪一轮核到的”。
