# 悬浮字幕显示逻辑重构（实时字幕引擎）

状态：Main 已拍板（2026-10-09）。用户的要求原话："字符占位是不动位置的，只能换行整体平缓上浮。"

## 0. 现状与根因（Main 读码确认）

| # | 问题 | 位置 |
|---|---|---|
| R1 | 当前句被改译（新整句不以旧整句为前缀）时走 `replace_text`，它 **`clear()` 整条轨**——连同之前已经说完的句子一起清掉，再从头排。屏幕上表现为整块字跳回左上、重新爬。 | `vox-core/src/subtitle.rs` `replace_text`；触发点 `pipeline/mod.rs` `push_text`（`strip_prefix` 失败 → `replace=true`）→ `runtime.rs` `on_subtitle_delta` |
| R2 | 改译后所有字 `born_ms` 重置，没变的字也重新淡入/计时。 | 同上 |
| R3 | 两条轨（听 / 说）的视觉行**排在同一个视口**里自底向上堆：说的那条多一行，听的那块整体被顶上去——你正在读的字被另一条轨推着动。 | `vox-overlay-core/src/layout.rs` `layout_rows_in_viewport` |
| R4 | 两套布局并存；`layout_rows` 在超宽时**从左侧滚掉旧字**，每来一个字整行左移一格。 | `layout.rs` `layout_rows` / `visible_tail`，`render.rs` 两处分支 |
| R5 | 逐字 TTL 淡出（行里出现透明空洞）+ 满 400 字整轨 `clear()`（整块突然消失）。 | `subtitle.rs` |
| R6 | 换行是逐字贪心：英文单词被拦腰截断；中日文行首可能出现"。"等禁则标点。 | `layout.rs` `wrap` |

## 1. 目标行为（不变量，全部要有自动化测试）

- **I1 位置不动**：一个字一旦摆上屏，只要它的内容没被服务端改掉，它相对所在轨的 (行号, x) 永远不变。改译只影响**从新旧整句第一个不同字开始**往后的部分。
- **I2 已封口的行不变**：某行下面已经有新行后，该行的字集合与每个字的 x 不再变化——除非改译的分歧点落在这行里。
- **I3 只整行上浮**：唯一的纵向运动是"整块向上平移一个行距"，用缓动动画（约 200ms，ease-out），不跳。没有任何横向运动。
- **I4 轨道独立**：一条轨上的任何事件不改变另一条轨的任何坐标。
- **I5 不丢旧句**：改译当前句永远不会让之前的句子消失或移动。
- **I6 墨迹在底衬内**（Linux 已有 `tests/ink_in_plate.rs`，保留并扩到新布局）。

## 2. 拍板

| # | 决定 |
|---|---|
| C1 | **字幕模型**（`vox-core/src/subtitle.rs`）改为"句子序列"：每条轨 = 若干已定稿句 + 一个进行中句。新接口：`update_sentence(full_text, confirmed_len, now)`（进行中句的最新整句；与旧整句按**字**求公共前缀，前缀内的字保留身份与 `born_ms`，其后的字替换为新字）与 `finish_sentence(final_text, now)`（同样做 diff，然后定稿）。删除 `replace_text` 与"整轨清空"的语义。句与句之间的分隔：前后两侧都是空格分词文字时补一个空格，CJK 不补。 |
| C2 | **喂入路径**：`pipeline/mod.rs` 把"到目前为止的整句 + 已确认前缀长度 + 是否定稿"交给 runtime，runtime 调 C1 的接口。对外事件 `Event::SubtitleDelta`（VRChat ChatBox、MCP 资源在用）的字段语义**保持不变**，现有相关测试逐字不改。 |
| C3 | **未确认尾巴**：`confirmed_len` 之后的字以 0.7 倍不透明度绘制（读者能看出"这段还会变"）；确认后恢复。没有确认信息的服务商整句按已确认处理。 |
| C4 | **唯一布局**：删 `layout_rows` 的横向滚动模式与 `visible_tail`。每条在跑的轨占一个**独立区域**，区域高度 = `lines_per_track` 行（新设置 `subtitle.lines_per_track`，1–4，缺省 2）；听在上、说在下；窗口高度由区域数 × 行数 × 行距决定，不随内容变（只在在跑轨数或字号/行数设置变化时变）。 |
| C5 | **增量折行**：按 UAX #14 求断行机会（加依赖 `unicode-linebreak`，纯 Rust 小库），贪心填行；单词比整行还宽时按字断。已封口的行冻结（I2）：后续追加导致的禁则问题（例如下一个字是"。"）用**行尾悬挂标点**解决——标点允许伸出行宽进右侧内边距，**绝不回头改已封口的行**。 |
| C6 | **上浮动画**：每个区域维护 `scroll_target = max(0, 总行数 − N) × 行距` 与 `scroll_pos`，`scroll_pos` 以约 200ms 的 ease-out 追 target；落后超过 1 行时把多出的部分瞬移（只保留最后一行的动画），避免爆发输入时一直拖着。正在移出区域顶部的那一行按被裁比例淡出。动画只在 `scroll_pos ≠ target` 时请求重绘。 |
| C7 | **底衬**：每个视觉行一块底衬，宽度贴合该行文字（YouTube 风格）；已封口行的底衬宽度不再变；底衬随行一起上浮。 |
| C8 | **淡出与清屏**：取消逐字 TTL。区域在最后一次更新后 `idle_ms`（复用现有 `char_ttl_ms` 设置的值与界面控件，界面文案改为"静默多久后淡出"）整体淡出（复用 `char_fade_ms`），淡完清空该轨。超出区域顶部、动画结束后已不可见的行从模型里丢弃（不会再显示，丢掉不影响 I1）。去掉 400 字整轨清空。 |
| C9 | **0 类字**（`dim_zeros`）：保留开关；0 类字始终以 `dim_alpha` 绘制，随区域一起淡出清空（不再"永久留"——新模型没有逐字生命周期）。界面说明文案同步。 |
| C10 | 平台：`vox-overlay-core` 承载全部布局/动画逻辑；`vox-overlay-linux` 与 `vox-overlay-win` 只适配新接口。Windows 用本机交叉检查：`cargo check -p vox-overlay-win --target x86_64-pc-windows-gnu --all-targets`（必须通过）。 |
| C11 | 复杂文字（阿拉伯语从右往左、泰语/印地语字形组合）**不在本单**；但折行与度量接口不要写死"一个 char 一个字形"，给后续接字形引擎留口子（报告里说明留在哪）。 |

## 3. 测试要求

- I1–I5 用**随机事件序列**的性质测试（不加 proptest 的话就用固定种子的简单伪随机）：随机生成"追加 / 改尾巴 / 改中段 / 定稿 / 另一条轨插话 / 时间推进"序列，每步检查不变量。至少 2000 条序列。
- 定向用例：英文长句按词换行；中文"。"落在行首时悬挂；单词超长按字断；爆发输入时动画落后不超过 1 行；改译中段只重排分歧点之后的部分；静默后整体淡出再清空。
- 关键不变量做**变异验证**：把 C1 的公共前缀 diff 改成整句替换 → I1/I5 必须红；把轨道区域合并 → I4 必须红。贴红的输出。
- Linux 截图：`crates/vox-overlay-linux/examples/snapshot.rs` 渲一组帧序列（中英混排、改译、上浮动画中间帧）存 PNG 到 `/tmp/claude-1000/overlay-captions/`，报告列出路径。

## 4. 不做
- 不改字幕外观设置以外的界面；新设置 `lines_per_track` 在字幕页加一个 1–4 的滑块或下拉（zh/en/ja 三语文案）。
- 不做复杂文字字形处理（C11）。
